第一层 · 风险告知（上线前必读）

🔴 P0 红线 · 开关来回切丢数据
开启生产批次管理后关闭再打开，原有生产批次信息一部分会丢失。属真问题。
防护：① 切换前全量导出批次库存快照；② 上线后严禁来回切开关；③ 出问题靠数据恢复而非关功能（因"开了不能关"，回滚=快照恢复）。

风险分级一览

高 · 无批次先发破 FIFO（跨仓同仓都先推无批次） 中 · 一位多批次回退受限 中 · 暂存位开关混存须关 中 · 拣货不扫批次·伪 FIFO 残留 中 · 编码来源被替换（擅自手编） 中 · 历史库存回填选错批次=盘盈 低 · 去箱后无批次难追溯
实话说明（伪 FIFO 残留）：同一库位放不同批次、拣货只扫仓位+SKU 不扫批次 → 系统记扣旧批、拣货员实际可能抓到顶部/最新的。这是"库存漂移/伪 FIFO"本质，但比现在完全没 FIFO 强——至少账面上强制批次顺序。彻底消除需开拣货批次扫码校验（暂未做），当前靠：①旧批放最易取处 ②商品贴批次码肉眼核对 ③同库位尽量单批次 ④卡板不码太高太深 ⑤定期盘点发现漂移。

D0 · 预约送货去留（全局卡点 · 所有分仓 · 二选一）
① 等聚水潭解决 R159775（时间不定） ② 取消预约送货，改走按箱入库 / 普通收货
开启生产批次管理后，现有「供应商预约送货」功能全局报错 该业务不支持生产批次流程！——这是系统层面冲突，不分仓，任何分仓只要走预约送货入库都会被卡。PLBG 仓重度依赖预约送货，受影响最重；其余分仓若也用预约送货同样被卡。这不是可防护的风险，是确定性卡点：要么聚水潭修好 R159775，要么停用预约送货、改走按箱入库/普通收货——二选一，且须在试点仓上线前先定。因涉及停用一个在用功能，此卡点可能需领导拍板。
D1 · 存储选型策略（在现有条件下怎么摆）
佳珞裴-总仓：严格存拣分离（拣货区+存储区） Soyama / Wholesale-1：卡板存储为主（大货整批） Wisco / PLBG / PuHuo：库内分区（轻量存拣分离）
建议默认如上：不做"全仓统一改存拣分离"，按分仓画像选型。层高有限，先走流程/软件固化，硬件（流利架/层板货架）等标杆跑顺再上。
D2 · 旧库存批次化策略（执行层决策，非领导拍板）
① 一次性：各分仓全部旧库存生成生产批次 ② 逐步：试点仓先批次化，其余随业务推进 ③ 不管旧库存：旧货自然销售完，仅新库存用批次管理
这决定"暂存位生产批次开关何时开"的前置条件：只有全仓都批次化（含旧库存）后才能开开关；若留旧库存无批次，则混存阶段须保持开关关闭。三种选法对应不同工作量与过渡期长度——由运营侧定，不是领导决策。
D3 · 两个开放问题定调（飞书文档遗留，批次码来源已转 D4）
保证期是否强制维护 商品贴日期是否影响客户体验
建议：食品/化妆品/电池强制维护保证期，普货留空=长期；内部批次码贴内盒封口/外箱不显眼处，不影响体验。批次码来源（工厂预印 vs 仓库贴）已定=以供应商贴标为准，其落地属跨部门协调，单列 D4，不在此选型。
D4 · 供应商贴标协调（需采购/供应链主导，非仓库职责）
① 纳入供应商准入 / 采购协议条款 ② 先头部供应商试点沟通模板 ③ 暂不推，仓库收货台兜底打印
FIFO 数据流源头在供应商，仓库无法强制。"让供应商贴 YYYYMMDD 批次码"能否落地、快慢如何，取决于采购/供应链何时把它变成供应商交付要求。属跨部门协调事项，非领导拍板、亦非仓内可单方面决定；过渡期由仓库收货台现场打印贴标兜底（见④脚注）。
CONFIRMED

第三层 · 已确认事实（验证确定，无需再议）

① 聚水潭能力底座：「生产批次管理」= FIFO 实现层，已覆盖东莞仓 6 分仓需求，无需自研代码。
② FIFO 数据流（命门在录入端）：供应商贴标 ⚠️需采购/供应链协调 → 收货扫标建批 → 上架扫标带出 → 拣货系统按"该仓位该 SKU 批次记录"自动 FIFO 指派最旧批次 → 出库。拣货不扫批次，FIFO 由系统保证，风险转移到"上架/盘点录得准不准"。数据流源头在供应商，仓库无法强制，详见第二层 D4。
③ 上架/盘点扫码自动带出：前提是批次先在系统维护，之后扫外箱批次标即自动带出、取消手选（解"上架还要选批次"痛点）。
④ 批次编码规则：以供应商贴的标签为准，扫描录入，不自编、不加后缀、不用系统流水号；格式严格 8 位日期 YYYYMMDD（如 20260811），其他格式一律禁止。⚠️ 此规则成立的前提是供应商配合贴码——需采购/供应链部门协调推动，属公司级跨部门事项，非仓库可单方面达成。若供应商短期不配合，兜底为仓库收货台现场打印贴标（见 D4）。
⑤ 贴码规则：外箱与产品盒都贴生产日期标签，且外箱标须 = 产品标（防内外错配）。
⑥ 全维护批次时按批次 FIFO；同进有/无批次，系统先推无批次（库位从小到大）。
⑦ 存货区简化流程（原生支持）：开启后可在仓位分别设存储区 / 拣货区，即存拣分离的平台入口。
⑧ 调拨已知约束：开启生产批次后，调拨不支持从暂存位发起，须从"他位"调拨到对应分仓；特别地佳珞裴总仓 → 百世云仓 路径要重点验证。（云仓 FIFO 不在本方案范围，由云仓自身负责，不验证。）
⑨ 卡板堆叠纪律：库位足够时铺开存放、不码太高太深，让旧批次始终停在易取层，物理上降低"随手抓到新批次"的概率，压低伪 FIFO 残留漏洞影响面。
⑩ 试点顺序已定：FIFO 对 6 个分仓均重要，差异只在推广顺序——先拿 佳珞裴-总仓 作标杆试点（覆盖全业务场景、日发货量小影响小），走顺后逐一落实其余分仓。此为非领导拍板的业务侧决定。

4.2 存储选型谱系（现有条件下 · 不靠买设备）

现实条件：仓库只有 普通货架 + 卡板 两种存储设备，层高约 4 米。下面三方案的区别，不在"要不要买设备"，而在"给这两种现有设备怎么分配角色、摆多严"。A/B 均零新增设备，用现有两设备当天即可落地。

4.2.1 存拣分离运作图示（B 方案核心）

把"存"和"拣"分到两个物理区：卡板整托囤在 存储区、普通货架拆零放 拣货区，中间用补货单联通。货进存储区 → 补到拣货区 → 从拣货区出，FIFO 的断层被压到最小。

岗位标准动作（扫什么）铁律 / 易错点异常怎么纠
收货员
入库建批		扫外箱生产批次标 → 系统按「生产批次号模式」建批入库外箱标 = 产品标；只扫日期（YYYYMMDD），不自编、不加后缀标签破损/扫不出 → 找主管核对供应商日期，收货台补打印，禁止手编
上架员
上架带出批次		扫商品码 → 扫仓位 → 扫批次标，批次自动带出（前提批次已在系统维护）同仓位尽量单批次；卡板不码太高太深，旧批放易取层批次带不出（未维护）→ 先建批再上架，不空着跳过
拣货员
按系统指派拣		按 PDA 指派仓位+SKU 拣，系统自动指派最旧批次（FIFO）拣货不扫批次，跟系统走；无批次货先拣、库位从小到大仓位没货 → 点「没有拣到货，跳过当前仓位」，不自行换批次
盘点员
回填/校准批次		无批次旧库存 →「商品盘点」一次性盘入该仓位 SKU 批次；有批次 →「商品单品盘点」选已有批次选错批次=盘盈；必须选已有批次，不新建旧库存分次盘会散落 → 一个仓位一次盘完，不分次
参数管理员
开关/参数		暂存位生产批次开关：混存阶段关、全批次化后开；存货区简化流程：开启后在仓位设存储区/拣货区生产批次开关严禁来回切（丢数据）；一位多批次改回一位一批次须先全部移成一位一批次切开关前先全量导出批次快照；出问题靠快照恢复，不关功能
